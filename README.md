# AbiLauncher

Настольный лаунчер **Minecraft Java Edition** на русском языке для Windows и Linux, ориентированный на авторские сборки с публикацией через публичные GitHub-репозитории.

## Основные возможности

- **Игры и загрузчики**: поддержка обычного Minecraft Java Edition (Vanilla), **Fabric**, **Forge** и **NeoForge** на совместимых версиях игры.
- **Изолированные сборки**: каждая сборка хранится в собственной папке `<installDir>/instances/<packKey>`, а общие ресурсы игры (`versions`, `libraries`, `assets`) переиспользуются в `<installDir>/shared`.
- **Управление Java**: автоматическое скачивание совместимой Java (официальные рантаймы Mojang + запасной источник Eclipse Adoptium/Temurin) и возможность ручного выбора/проверки установленной Java.
- **Обязательная предпусковая проверка через GitHub**: перед каждым запуском лаунчер сверяет актуальность `pack.json` и `manifest.json` на GitHub (кэш витрины не подменяет проверку; при отсутствии сети или ошибке манифеста запуск блокируется). Недоступность только новостей или статуса сервера игру не блокирует.
- **Надёжная докачка и атомарное применение**: HTTP Range-докачка (`.part`), проверка размера и SHA-256 в `.abilauncher/staging/`, перенос в рабочую папку сборки только после полной проверки всех файлов.
- **Защита файлов игрока**: сохранение миров (`saves/`), скриншотов (`screenshots/`), ресурс-паков, шейдеров, `options.txt` (`mode: initial`) и дополнительных модов (с предупреждением о возможной несовместимости). Учёт управляемых файлов в `.abilauncher/state.json`, создание резервных копий в `.abilauncher/backups/` перед заменой конфликтных файлов.
- **Локальные профили**: профили по никнейму с расчётом offline UUID (подходят для одиночной игры и серверов без проверки аккаунта Microsoft; не подходят для лицензионных серверов).
- **Интерфейс**: светлая и тёмная темы (по умолчанию — системная тема с отслеживанием изменений ОС), живой прогресс со скоростью, мониторинг статуса Minecraft-серверов, новости сборок, журнал работы и экспорт обезличенного диагностического отчёта.

## Архитектура и технологии

- **Оболочка**: Electron (`contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, строгий CSP в продакшене и валидация каждого IPC-вызова через Zod).
- **Интерфейс**: React 19 + TypeScript (без прямого доступа к Node.js или сети из renderer).
- **Ядро установки и запуска Minecraft**: `@xmcl/core` + `@xmcl/installer` (поддержка Vanilla, Fabric, Forge, NeoForge, диагностика установки и управление процессами).
- **Архивы и валидация**: `yauzl` / `yazl` / `tar` (с проверкой путей и запретом Zip Slip / симлинков), `zod`.

### Структура каталогов

```text
src/
  shared/     # Чистые схемы Zod, валидация относительных путей, общие IPC-типы
  core/       # Независимая от Electron логика: каталог, HTTP/докачка, архивы,
              # сверка/обновление сборок, Java, установка MC/загрузчиков, запуск,
              # TCP-пинг серверов, диагностика, хранилище настроек/профилей
  preload/    # Ограниченный contextBridge API (window.abi)
  main/       # Окно Electron, безопасность, системная тема, IPC-обработчики
  renderer/   # React UI (6 экранов на русском языке)
tools/
  publish/    # CLI-утилита build-manifest.ts для подготовки релизов сборок
examples/     # Демонстрационные примеры catalog.json, pack.json, news.json, manifest.json
catalog/      # Каталог сборок по умолчанию для Abi_Launcher
docs/         # Инструкция публикации сборок и обновлений (PUBLISHING.md)
tests/        # Автотесты Vitest
```

## Локальный запуск и разработка

Требуется Node.js 22+ (рекомендуется LTS) и npm.

```bash
# Установка зависимостей
npm install

# Запуск в режиме разработки
npm run dev

# Проверка типов TypeScript
npm run typecheck

# Запуск автотестов
npm test

# Сборка production-бандла (main + preload + renderer)
npm run build
```

## Упаковка для Windows и Linux

Конфигурация сборки установщиков находится в [`electron-builder.yml`](./electron-builder.yml).

### Windows (NSIS-установщик и Portable `.exe`)

```bash
npm run dist:win
```

Готовые артефакты появятся в папке `dist/`.

### Linux (AppImage, `.deb` и `.tar.gz`)

На Linux (или в Linux-контейнере / CI):

```bash
npm run dist:linux
```

Готовые файлы (`AbiLauncher-*.AppImage`, `*.deb`, `*.tar.gz`) появятся в `dist/`.

## Публикация сборок и обновлений

Подробная инструкция по структуре GitHub-репозиториев, ограничениям GitHub, использованию `npm run pack-tool` и списку данных для заполнения перед первым запуском приведена в [docs/PUBLISHING.md](./docs/PUBLISHING.md).

## Обновление самого лаунчера (следующий этап)

Обновление исполняемых файлов **самого AbiLauncher** намеренно отделено от механизма обновления игровых сборок. В качестве следующего этапа развития рекомендуется добавить отдельный канал проверки релизов лаунчера (`AbiBok89/Abi_Launcher` Releases) через `electron-updater` с проверкой цифровой подписи бинарных файлов.
